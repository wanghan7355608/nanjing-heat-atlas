# 三分钟复试讲解稿

## 0:00–0:35：为什么做

“我做的是一个南京城市热环境图谱。它不是一张静态热力图，而是从 Landsat Level-2 原始资产到可交互地图的一条可复现链路。我想回答：在一次夏季卫星过境时，南京不同网格的地表温度和植被分布有什么空间关系？”

打开网页，展示影像日期、平均地表温度、有效像元比例和网格数。

## 0:35–1:25：怎么做

“我通过 STAC 定位影像，使用 COG 的 HTTP Range 读取南京范围，因此不用下载整景。先用 QA_PIXEL 排除云、云影、雪和水，再按产品元数据的 scale/offset 把 ST_B10 换算为摄氏度，把红光和近红外算成 NDVI。随后在 UTM 50N 下聚合到 500 米网格，只保留有效覆盖率不低于 60% 的网格。”

切换三个图层，点开一个网格，展示温度、NDVI、植被占比和有效覆盖。

## 1:25–2:15：发现了什么

“这景影像的样区有效像元约占 76.2%，发布了 2046 个网格。地表温度与 NDVI 的网格相关系数约为 -0.872。散点图说明本景样区里高植被指数网格通常较凉，但我没有把这解释成植被单独造成降温，因为建筑密度、地形等都可能影响温度。”

展示散点图与来源清单。

## 2:15–3:00：能否信任以及后续

“我把影像 ID、时间、QA 位、阈值和网格结果一起提交，并用测试覆盖关键公式。这个结果是一次卫星过境的地表温度，不是气温，也不能代表长期热岛趋势。下一步我会用多日期合成、LCZ 或建筑密度控制变量，并用地面站数据做验证。”

## 可能追问

**为什么用 UTM 而不是经纬度直接划网格？** 500 米是距离单位，投影坐标更适合等边长空间统计；网页展示时再转回 WGS84。

**为什么不直接拿 ST_B10 原值？** Level-2 整型像元带 scale 和 offset，不换算就不是物理温度。

**为什么不把相关系数做成结论？** 空间网格并非独立样本，且建筑、地形等变量没有控制。当前 r 只能描述这张影像的空间关系。

**为什么部分地方地图没有颜色？** 水体、云/阴影或覆盖率低于门槛的网格不发布，避免把不可靠值插值成“完整”地图。

**为什么代码分管线和网页？** 管线是唯一的科学计算来源，网页只读取带来源清单的派生结果，避免展示层重复实现公式导致分歧。
