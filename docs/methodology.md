# 数据与方法

## 研究问题

在一景晴空 Landsat 8 影像中，南京主城区样区的地表温度如何分布？500 米网格的植被指数与地表温度有什么描述性关系？

本项目回答的是**空间快照**，不是气象预报、热健康风险评估或因果推断。

## 来源与空间范围

- STAC Collection：`landsat-c2-l2`。
- Item：`LC08_L2SP_120038_20240809_02_T1`，采集时间 2024-08-09 02:36:55.915 UTC。
- WGS84 样区：`[118.68, 31.99, 118.95, 32.22]`。
- 原始栅格：UTM zone 50N（EPSG:32650）、30 米像元。
- 使用资产：`lwir11`（ST_B10）、`red`（SR_B4）、`nir08`（SR_B5）、`qa_pixel`（QA_PIXEL）。

项目从 STAC 获取资产地址、临时签名并按窗口读取；不会把签名或整景原始影像存入仓库。`manifest.json` 记录源条目、参数与摘要。

## 质量控制与公式

拒绝 QA_PIXEL 的位 0（填充值）、1（扩张云）、2（卷云）、3（云）、4（云影）、5（雪）和 7（水体）。同时拒绝零值热红外或反射率原始值，以及不能计算有效 NDVI 的反射率。水体被排除，是为了比较**陆地**的地表温度与植被；河面不参与相关系数。

根据 Landsat Collection 2 Level-2 资产元数据：

```text
LST (°C) = ST_B10 × 0.00341802 + 149 − 273.15
反射率 = SR_B4 或 SR_B5 × 0.0000275 − 0.2
NDVI = (近红外反射率 − 红光反射率) / (近红外反射率 + 红光反射率)
```

以 EPSG:32650 的整 500 米坐标为原点建立方格。每格计算有效像元平均 LST、平均 NDVI、NDVI≥0.30 的比例和高温像元比例。有效像元数至少 25，且占该格窗口像元的 60% 以上，才发布该格。高温阈值定义为**本景有效陆地像元**的第 75 百分位数，不是气象预警阈值。

散点图每点代表一个发布网格。相关系数是这些网格平均 NDVI 与平均 LST 的 Pearson r，没有显著性检验或因果解释。空间自相关会大幅降低网格之间的独立性，见下节。

## 空间自相关与有效样本量

网格数不是样本数。相邻 500 米网格共享同一片地形、同一条街道走向和同一团空气，信息高度重叠。对已发布的网格做相关图分析，LST 的等值相关随距离衰减如下：

```text
间隔(km)  相关系数
   0.50      0.759
   1.10      0.536
   1.50      0.465
   2.50      0.328
   3.50      0.171
   4.50      0.054
   5.50     -0.026
```

相关长度（r 降到 0.5 的距离）约 **1.3 公里**。按 `n_eff ≈ n × (d / L)²` 折算，2046 个网格约相当于 **300** 个独立样本，比网格数少一个数量级。因此本项目不报告基于 n = 2046 的显著性检验或置信区间。

这不改变 r = −0.872 作为**描述性统计量**的值，只影响推断：即便按 300 的有效样本量，0.1% 显著性阈值也只有约 0.19，r 仍远超它。要更严格地处理，应改用半变异函数拟合相关长度，或做空间分块交叉验证。

复现：`python -m heat_atlas.autocorrelation`（仅依赖标准库，读取已提交的派生数据）。

## 验证与局限

- `tests/test_analysis.py` 覆盖 QA 位排除、官方缩放系数、网格聚合和零有效像元错误。
- `tests/test_generated_data.py` 校验提交的派生数据结构、来源清单和数值范围。
- 前端构建与交互布局在桌面和手机宽度检查。

局限包括：Landsat 30 米分辨率无法解析细小街道；过境时刻不代表一天的最高温；云、云影和水体剔除后仍有约 23.8% 样区像元不参与统计；一次影像不能定义多年趋势。建筑材料、建筑形态、地形和人为热排放也会影响 LST。本项目没有地面站验证、没有控制混杂变量，因此只能描述相关性。

## 复现证据

默认 CLI 会从指定 STAC Item 重新读取窗口并覆盖 `web/public/data/` 中的两份派生文件。页面中的数字和 `manifest.json` 都来自同一次管线运行。重新运行时生成时间会变化，影像与算法参数不变时数值应保持一致。
